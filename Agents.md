# ZeroDaily Backend Architecture & API Specification

This document serves as the master architectural reference, API contract, and implementation guide for developers and autonomous agents building the ZeroDaily backend serving infrastructure (`api.zerodaily.in`).

## 2. Storage & Database Schema

All primary data resides in **Amazon DynamoDB** in `us-east-1` with on-demand capacity (`PAY_PER_REQUEST`).

### Table: `zerodaily-articles`
Primary store for enriched, roasted news articles across 6 domains.

- **Primary Key:**
  - Partition Key (`HASH`): `id` (`String`, the original canonical article URL)
- **Attributes:**
  - `id` (`String`): Canonical source URL.
  - `category` (`String`): One of `cybersec`, `ai`, `programming`, `robotics`, `defense_aerospace`, `hardware`.
  - `published_at` (`String`): ISO-8601 UTC timestamp (e.g. `2026-09-16T08:30:00Z`).
  - `feed_bucket` (`String`): Fixed value `"ALL"`. Used for global feed indexing.
  - `title` (`String`): Original source headline.
  - `heading` (`String`): Satirical roasted headline generated by Bedrock DeepSeek.
  - `shortSummary` (`String`): Witty, condensed bullet/paragraph summary.
  - `fullSummary` (`String`): Complete multi-paragraph roasted story breakdown.
  - `image_url` (`String`): Cloudflare CDN URL: `https://media.zerodaily.in/images/{category}/{hash}.webp`.
  - `link` (`String`): Link to original source article.
  - `scraped_at` (`String`): ISO-8601 UTC timestamp of ingestion.

#### Global Secondary Indexes (GSIs)

1. **`CategoryIndex`** (Filtered Category Feed)
   - **Partition Key (`HASH`):** `category` (`String`)
   - **Sort Key (`RANGE`):** `published_at` (`String`)
   - **Projection:** `ALL`
   - **Query Pattern:** Retrieve latest articles for a specific category sorted newest first.

2. **`GlobalFeedIndex`** (Unified Cross-Category Feed)
   - **Partition Key (`HASH`):** `feed_bucket` (`String`, always `"ALL"`)
   - **Sort Key (`RANGE`):** `published_at` (`String`)
   - **Projection:** `ALL`
   - **Query Pattern:** Retrieve latest articles across all 6 categories sorted newest first.

---

### Table: `zerodaily-scrape-metrics`
Telemetry store for scraping runs and Lambda compute tracking.

- **Partition Key (`HASH`):** `metric_date` (`String`, format `YYYY-MM-DD`)
- **Sort Key (`RANGE`):** `metric_id` (`String`, format `{ISO_TIMESTAMP}#{category}`)
- **TTL Attribute:** `ttl` (Unix epoch integer, auto-deletes records after 30 days)
- **Attributes:** `category`, `duration_seconds`, `memory_mb`, `gb_seconds`, `articles_scraped`, `articles_summarized`, `status`, `timestamp`.

---

### Table: `zerodaily-users`
User account profile, auth credentials, reading history, and feed personalization weights.

- **Primary Key:**
  - Partition Key (`HASH`): `user_id` (`String`, e.g. `usr_...`, `guest_...`, `fb_...`)
- **Attributes:**
  - `user_id` (`String`): Primary unique user identifier.
  - `email` (`String`, optional): Lowercase user email address.
  - `password_hash` (`String`, optional): Bcrypt hash of user password.
  - `display_name` (`String`, optional): User handle or profile alias.
  - `avatar_url` (`String`, optional): Profile picture URL.
  - `is_anonymous` (`Boolean`): `true` for guest accounts, `false` for registered users.
  - `created_at` (`String`): ISO-8601 UTC timestamp.
  - `last_active_at` (`String`): ISO-8601 UTC timestamp.
  - `topic_preferences` (`Map<String, Boolean>`): Subscriptions per category (`cybersec`, `ai`, `programming`, `robotics`, `defense_aerospace`, `hardware`, `finance`).
  - `algo_weights` (`Map<String, Number>`): Dynamic category affinity multipliers (default: `1.0`, tuned dynamically between `0.1` and `3.0`).
  - `bookmarked_articles` (`List<String>`): Array of canonical article URL IDs.
  - `reading_history` (`List<Map>`): Bounded sliding window of last 50 interactions with dwell durations.
  - `reading_count` (`Number`): Total count of stories read.

#### Global Secondary Indexes (GSIs)
1. **`EmailIndex`**
   - **Partition Key (`HASH`):** `email` (`String`)
   - **Projection:** `ALL`
   - **Query Pattern:** Fast user lookup during login and duplicate registration detection.

## 3. Media & Image Pipeline (`media.zerodaily.in`)

### Why Raw Third-Party URLs Are Forbidden
1. **Hotlink Blocking:** News publishers actively block mobile user-agents or referrers.
2. **Dead Links:** External URLs change or break within weeks.
3. **Bandwidth Bloat:** External images range from 2MB to 8MB uncompressed.

### The ZeroDaily Image Lifecycle
1. During ingestion, the scraper extracts the hero image URL.
2. The image is downloaded into memory, resized to a maximum width of `800px` (preserving aspect ratio), and compressed into `WebP` format (quality 80).
3. The compressed image (~30KB to 60KB) is uploaded to S3:
   - **Bucket:** `zerodaily-article-images` (Region: `us-east-1`)
   - **Key:** `images/{category}/{md5_hash_of_url}.webp`
   - **Content-Type:** `image/webp`
   - **Cache-Control:** `public, max-age=2592000` (30 days)
4. The database stores the CDN URL:
   `https://media.zerodaily.in/images/{category}/{md5_hash_of_url}.webp`
5. Cloudflare proxies `media.zerodaily.in` directly to the S3 bucket with edge caching enabled.

## 4. API Endpoints Specification (`api.zerodaily.in`)

Base URL: `https://api.zerodaily.in`

### 1. Global Chronological Feed
Returns the unified feed across all 6 tech categories, sorted newest first.

- **Path:** `GET /api/v1/feed`
- **Query Parameters:**
  - `limit` (`int`, optional, default: `20`, max: `50`): Number of items to return.
  - `cursor` (`string`, optional): ISO-8601 UTC timestamp from `pagination.next_cursor` of the previous page.
- **Cache Header:** `Cache-Control: public, max-age=60, s-maxage=300, stale-while-revalidate=600`
- **Response `200 OK`:**
```json
{
  "status": "success",
  "data": [
    {
      "id": "https://example.com/ai-breakthrough",
      "category": "ai",
      "heading": "OpenAI Released Another Model, Server Fans Begin Sweating",
      "shortSummary": "A condensed roast on the latest model drop.",
      "fullSummary": "Full analytical and satirical breakdown...",
      "published_at": "2026-09-16T12:00:00Z",
      "link": "https://example.com/ai-breakthrough",
      "image_url": "https://media.zerodaily.in/images/ai/c8f2a1b9.webp"
    }
  ],
  "pagination": {
    "has_more": true,
    "next_cursor": "2026-09-16T08:15:00Z",
    "count": 20
  }
}
```

### 8. User Interaction & Telemetry Tracking
Telemetry beacon for training the user's category feed weights.

- **Path:** `POST /api/v1/auth/track`
- **Headers:** `Authorization: Bearer <token>`
- **Request Body:**
```json
{
  "article_id": "https://example.com/cyber-breach",
  "category": "cybersec",
  "action": "read",
  "duration_seconds": 15.5
}
```
Supported `action` values:
- `read` / `dwell` / `full_roast`: Increases weight (`+0.15` up to `+0.65` depending on dwell duration), increments `reading_count`.
- `bookmark`: Increases weight (`+0.30`).
- `share`: Increases weight (`+0.25`).
- `skip`: Decreases weight (`-0.05`).

## 5. DynamoDB Query Logic & Pagination Patterns

### A. How to Query the Global Feed (Python / Boto3)

```python
from boto3.dynamodb.conditions import Key

def query_global_feed(limit: int = 20, cursor: Optional[str] = None) -> dict:
    table = dynamodb.Table("zerodaily-articles")

    if cursor:
        key_condition = Key("feed_bucket").eq("ALL") & Key("published_at").lt(cursor)
    else:
        key_condition = Key("feed_bucket").eq("ALL")

    response = table.query(
        IndexName="GlobalFeedIndex",
        KeyConditionExpression=key_condition,
        ScanIndexForward=False,  # Newest first
        Limit=limit
    )

    items = response.get("Items", [])
    next_cursor = items[-1]["published_at"] if len(items) == limit else None

    return {
        "items": items,
        "next_cursor": next_cursor,
        "has_more": next_cursor is not None
    }
```

### B. How to Query a Category Feed (Python / Boto3)

```python
from boto3.dynamodb.conditions import Key

def query_category_feed(category: str, limit: int = 20, cursor: Optional[str] = None) -> dict:
    table = dynamodb.Table("zerodaily-articles")

    if cursor:
        key_condition = Key("category").eq(category) & Key("published_at").lt(cursor)
    else:
        key_condition = Key("category").eq(category)

    response = table.query(
        IndexName="CategoryIndex",
        KeyConditionExpression=key_condition,
        ScanIndexForward=False,  # Newest first
        Limit=limit
    )

    items = response.get("Items", [])
    next_cursor = items[-1]["published_at"] if len(items) == limit else None

    return {
        "items": items,
        "next_cursor": next_cursor,
        "has_more": next_cursor is not None
    }
```

## 6. Cloudflare CNAME & Edge Configuration

To connect custom domains without AWS Certificate Manager overhead:

### 1. DNS Records (Cloudflare Dashboard)

| Type | Name | Target / Content | Proxy Status |
| :--- | :--- | :--- | :--- |
| `CNAME` | `api` | `<your-lambda-url-or-apigw-domain>.on.aws` | **Proxied (Orange Cloud)** |
| `CNAME` | `media` | `zerodaily-article-images.s3.us-east-1.amazonaws.com` | **Proxied (Orange Cloud)** |

### 2. Cloudflare Cache Rules
1. **Rule 1: Feed Caching (`api.zerodaily.in/api/v1/feed*`)**
   - **Cache Status:** Eligible for cache
   - **Edge Cache TTL:** Respect origin headers (or Override to 5 minutes)
   - **Browser Cache TTL:** 1 minute
   - **Stale While Revalidate:** Enabled (Cloudflare will serve cached content while fetching fresh data in background)
2. **Rule 2: Media Caching (`media.zerodaily.in/images/*`)**
   - **Cache Status:** Eligible for cache
   - **Edge Cache TTL:** 30 days
   - **Browser Cache TTL:** 7 days

## 7. Mobile Client Inshorts Swiper Algorithm

For the frontend/app developer:

1. **Initial Boot (0ms UI Render):**
   - App loads the last 20 cached cards directly from the local device database (SQLite / Hive / Room / CoreData).
   - Display rendered immediately without network latency.
2. **Background Network Sync:**
   - Call `GET https://api.zerodaily.in/api/v1/feed?limit=20`.
   - Compare top item `published_at` against local top item.
   - If newer items exist, prepend to local storage.
3. **Pre-fetching Threshold:**
   - When the user swipes to card index `N - 8` (e.g. card 12 of a 20-card batch), trigger:
     `GET https://api.zerodaily.in/api/v1/feed?limit=20&cursor={last_card_published_at}`
   - Save the next 20 cards and pre-cache their `image_url` WebP assets into the mobile disk cache.
   - The user will never encounter a loading spinner during normal swiping.
